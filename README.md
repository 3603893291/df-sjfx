# 三角洲 · 全面战场数据分析

Windows 桌面软件。**软件内置浏览器，登录 WeGame 后**自动采集你的战绩，做深度分析。
覆盖**胜者为王 / 指挥官 / 攻防占领**全部模式，支持多账号，数据仅存本机。

## 快速开始

1. 双击 `dist/三角洲全面战场分析器/三角洲全面战场分析器.exe`
2. 点「打开登录窗口」，在弹出的窗口里登录 WeGame（扫码或账号登录都行）
3. 登录成功后自动进入主界面；点左下角「立即同步」开始采集首次数据（启动时不再自动同步）
4. 断网 / 官方接口不通 / 登录态过期时，登录页会出现 **「跳过，直接看本机数据」**，本机已有的场次可以离线查看全部分析
5. 需要添加第二个号：侧栏顶部账号下拉旁边的 **＋**，或 **设置 → 账号 → ＋ 添加账号**

> 首次运行若显示空白/异常，请确认 `dist/三角洲全面战场分析器/` 整个文件夹完整（绿色版不能只拷 exe）。

## 功能

### 采集
登录后自动调用官方接口（不依赖页面结构，抗前端改版）：

| 接口 | 用途 |
|---|---|
| `GetRoleInfo` | 账号资料、登录态校验 |
| `GetBattleReport` | 赛季汇总（官方口径，仅作参考） |
| `GetMapStats` | 官方分地图统计（仅作参考） |
| `GetBattleList` | 战局列表。**单页返回 8 条、游标只挪 7 条，翻满 5 页到 36 条（阶梯 8/15/22/29/36）**，全部模式 |
| `GetBattleDetail` | **单场全场 46~57 人名单**，全部模式都抓 |

> 采集**不再限制模式**，胜者为王只是筛选条件之一。翻页数与翻页间隔在设置里可调（1~5 页 / 200~2000 ms）。
> 全场名单按「还缺名单的场次」抓取：每轮同步只补当前 5 页内没有名单的场次，
> 已有名单的不重复请求；某一场这次没抓到，下一次同步会自动补上。

### 采集进度
同步过程中侧栏底部会显示 4px 进度条 + 百分比 + `当前阶段 done/total`，
覆盖 6 个阶段：登录检测 → 赛季汇总 → 最近战局（含 5 页翻页） → 分地图统计 → 全场名单 → 入库。

### 多账号
- 侧栏顶部账号下拉，一键切换。**每个号一份独立数据文件 + 独立登录分区**（`df-swtwr-<slot>.json` / `Partitions/wegame-slot-<slot>/`），互不污染。
- **＋ 添加账号** 打开登录窗，扫码后自动分配下一个 slot 号；openid 已注册则直接切过去。
- ★ **每次「打开登录窗口」都会先把这一个号的旧登录痕迹清干净**（cookie / 本地存储 / IndexedDB / 缓存 / 历史），
  官方页面于是从一次**全新会话**开始。对付的是这个毛病：WeGame 隔一阵会自己把账号退掉，罐子里留下半死会话 ⇒
  网页显示「无角色信息」、软件两套账号体系都问不到角色，人就永远卡在登录页。
  只动**这一个号**的那一份分区，别的号的登录态不受牵连；「退出登录」「移除账号」仍按原来的语义只清 cookie。
- **设置 → 账号** 面板可查看每个 slot 的 openid 短码 / 场次数 / 名单数 / 最后同步时间，并支持 切换 / 移除 / 退出登录。
- 「退出登录」只清 cookie，数据保留；「移除」还会删除该 slot 的数据文件，Electron 分区目录需手动清理（软件会打印路径）。
- v1 单号数据首次启动自动迁移为 `slot=a1`，原文件归档为 `df-swtwr-data.v1.bak.<时间戳>.json`，同时生成 `migration-report.txt`。
- 从 v1.0.0 升级时**登录态一并继承**到新分区，不需要重新扫码（仅当官方会话本身未过期）。

### 去重
- 相同 `roomId` 重复同步 → 只计一次
- 相同 `开始时间 + 地图` 重复 → 视为同一场，不计入
- **跨号不判重**：A 号打过的场次，B 号如果同样参与（同一 roomId 落到 B 号的 payload 里），会正常入 B 号的库

单次同步最多翻到 36 场，定时同步会自动累积成完整历史库。

| 筛选项 | 取值 |
|---|---|
| 模式 | 全部 / 胜者为王 / 指挥官（手动标记的场次） / 其他模式 |
| 中途退出 | 全部 / 排除退出 / 仅退出 |
| 时间 | 全部 / 近 1 / 7 / 30 / 90 天 |

### 单场标注（v1.2.0）

开关只在「单场详情」页，两个标注互不影响，可以同时打：

| 标注 | 效果 |
|---|---|
| **标记为指挥官**（v1.3.0 起仅胜者为王对局提供） | 这一场**同时**出现在「胜者为王」和「指挥官」两个筛选下。战局仍然只有一条记录，不会被复制、也不会从胜者为王里搬走。因此计数口径变为 `全部 = 胜者为王 + 其他`，`指挥官 ⊆ 胜者为王` |
| **本场不纳入统计** | 这一场从胜率、战局总览、趋势、分地图、兵种表现、对手队友、地图×干员矩阵等**一切分析**中剔除；战局列表里仍保留该行（灰显 + 「已排除」徽标），随时可恢复 |

- 标注按 `room_id` 存在 `state.flags` 表里，不写进 match 原始字段：同一场被重新采集、重建对象都不会丢标注。
- 分析读到的 `is_commander` / `excluded` 由 `store.prune()` 在每次保存时物化到 match 上，所以标完立即生效，不需要重新同步或重启。
- 「完整数据包」导出/导入与 JSON 导出都会带上标注（导入时以本机已有标注为准，不会被包里的旧值覆盖）。
- **指挥官只认手动标记**：v1.1.x 里按「赤枭 / 赤枭亲卫」兵种或 613 地图自动判定的口径已废弃——那两类单位不等于当过指挥官。升级后原先被自动算作指挥官的场次会自动归零。
- **指挥官标记仅限胜者为王**（v1.3.0）：指挥官是胜者为王里的角色，常规对局的详情页不出现该按钮；即使越过界面直接调 `data:flag`，`store.setMatchFlag()` 也会拒绝，导入的外部数据包里若有「常规对局标了指挥官」的脏标注，`prune()` 物化时同样归零。「本场不纳入统计」不受模式限制，始终可用。

### 同场玩家的身份识别口径（重要）

官方 `GetBattleDetail` 返回的 `vopenid` 分两种：

| 类型 | 实测占比 | 能否跨局追踪 | 本软件做法 |
|---|---|---|---|
| 稳定账号 ID（19~20 位） | 约 54% | 能 | 按 `id:` 聚合，最可靠 |
| **当局临时编号（4 位）** | 约 46% | **不能** | 按**昵称**聚合，界面标注橙色「昵称」徽标 |

临时编号每局重新分配——实测编号 `8007` 在 8 场里对应 8 个不同的人。
若直接拿它当身份键，会把 8 个陌生人合并成「一人同场 8 次」，得出纯属虚构的结论。

> 另外：分边是随机的，双方各 25~36 人，同阵营概率天然约 50%，
> 因此本页看的是「同阵营率」相对 50% 的偏离；同阵营 ≠ 组队队友。

### AI 深度分析（v1.7.0 起不再是内置功能）

原来内置的那一页已经整体搬进**由使用者自己导入的插件包**（源码 `plugins-src/ai-analyst`，包 id `df.ai.analyst`）。
本软件自带功能里不再有任何发往第三方大模型的能力：侧栏 12 个视图与设置页都没有它的入口，
`df.ai` 桥、`shell/adapters/ai.js`、`ui/js/aiMarkdown.js` 也一并从出厂树里删掉 ——
`test/isolation.test.js` 与 `--selftest` 两头都钉着这条（服务商品牌、协议记号、那句确认、那颗导航，都不许留在出厂树与界面里）。

功能没有降级，只是换了住的地方。防线与知识的分界线是这条：**协议、话术、提示词、渲染归插件包；出口、闸门、数据边界归宿主。**

| 谁守 | 守什么 |
|---|---|
| 宿主（主进程） | 逐字确认那道闸门（句子来自清单，改一句就得重新导包）；两份联网包的清单都显式写成 `hosts:["*"]`——**哪个服务商都不预置，地址由使用者在插件页里自己填**，宿主守的是出口而不是名单：只放行 https 标准端口（明文 http 只认本机回环）、重定向逐跳复校、永不带登录 Cookie；`Cookie` 等危险头由宿主管；一个插件同时只许一条流；三个时间窗口（连接 120s / 断流 30s / 总计 600s）与 4 MB 上限；密钥独立文件 `plugin-data/<id>.secret.json`（不进导出包、不匹配备份名、卸载即删，`kv.get` 扫不到值）；去敏摘要在本机生成后经 `read.digest` 交出文字，单场用**一次性号牌**换（重启即失效，房间号结构上不出去）；同步成功只记一笔待办，要出日报得有人开着页按按钮；撤销 / 停用 / 卸载立刻掐断正在跑的流 |
| 插件包 | 服务商预设与地址解析、OpenAI 兼容协议、SSE 拆包与"无视 stream:true 直接回 JSON"的回落、错误码翻译、系统提示词、Markdown 白名单渲染（宽表自套 `.pl-scroll`）、本机历史索引与旧数据搬迁 |

摘要口径一字未改：只发聚合统计与单场逐人数值，同场玩家换成一次性代号（`队友A`…`对手1`…），自己的昵称换成「我」；
`openid` / `vopenid`、房间号、登录凭据与 WeGame 会话、逐场原始明细都发不出去（宿主本来也不给）。
体积与场次无关地恒定（★ 2026-09-22 用真机库实测：33 场的全局摘要 5444 字节、最大的一份单场摘要 9203 字节，硬上限 12000 字节），
不会因为库越大越烧额度。

旧版本机里存过配置与历史的，插件页上有一次性的「搬进来（只此一次）」按钮：
本机那份当场改名留底（`ai-config.json.migrated`）并从数据文件里摘走，**不静默复制、也不删**。

用过旧版内置页的，有三处行为差异要说在前面：

1. **单场详情页上那颗发起 AI 点评的按钮没有了**（原先它在标注开关那一排里），且不留占位。单场点评改在插件页里发起：
   页内「整体深度报告 / 单场点评」两档切换，选单场时从本机的对局列表里挑，宿主发一张进程内的一次性号牌去换那份摘要。
2. **全局摘要不再跟随顶栏的模式 / 天数筛选**。旧版是把界面当前的筛选条件一路带进 `buildGlobalDigest(store, filters)`；
   现在插件页自己定口径，「整体」一律按全库取数（宿主侧 `mode` / `days` 两个参数留着，本批插件没用到）。
3. **同步成功后不再自动出日报**。旧版是 `runSync()` 收尾直接调 `autoDailyReport()`；现在主进程只往
   `plugin-data/triggers.json` 记一笔（**绝不在主进程跑插件代码**），下次打开插件页时看到一句
   「同步之后你还没打开过这一页（共记了 N 次）。要现在出一份日报吗？」，按下去才发。
   那个开关也改名叫「同步后提醒我出日报」。

本批明确不做：多轮自由续聊（每次仍是「摘要 + 一句指令」，上下文不累积）、按服务商计价与重试队列、可点击外链、密钥加密混淆、本地推理。

### 扩展插件（v1.5.0 起，默认不带；v1.6.0 把外发闸门收到宿主；v1.7.0 起宿主能承载联网流式插件）

**软件自带功能里没有任何上传、外发到第三方站点的能力，也没有为某个站点写死的对接代码。**
需要往外走数据的功能一律做成插件包（`.zip`），由使用者自己获取、自己在「设置 → 扩展插件」里导入。
不导入就没有这条路，界面上也看不出这里有这个功能——左侧栏的「扩展页面」只在**导入了带页面的插件并启用**之后才出现。

插件能申请的能力只有六项，写在 `core/plugin.js` 的白名单里，界面上的权限说明与白名单同源生成（杜绝"代码里给了、界面上没说"）：

| scope | 给什么 | 不给什么 |
|---|---|---|
| `view` | 左侧栏加一页，页面完全由插件绘制 | 改宿主其它页面、注入宿主 DOM |
| `read.summary` | 聚合数字（场次、胜率、KD、场均、趋势窗口、平均分） | 逐场明细、房间号、玩家名单、`openid` |
| `storage` | 一块只属于本插件的本机存储（≤64 KB/值） | 别人的存储、宿主数据文件、导出包 |
| `read.digest` | 宿主在本机生成好的**去敏分析摘要**（一段文字） | 原始 store、逐场明细、房间号——插件拼不出摘要，也就改不了要外发的内容 |
| `read.legacy` | 一次性搬入旧版本机记录（点一下按钮才给，给完即归档） | 第二次领取：取走一次就报「本机没有可搬的旧记录」 |
| `net.request` | 经宿主代发请求（含流式 `net.stream`），只能打到**使用者自己在插件页里填的那个地址**（清单写成 `["*"]`，宿主不预置域名），只许 https 标准端口，**且要先由使用者在宿主面板里逐字确认** | 明文 http（本机自测除外）、非 443 端口、自己管 Cookie、未经确认的任何一次出网 |

边界怎么保证的（都在主进程，改插件页面没用）：

- 导入时**逐项全部勾选**才装（缺一项就拒），装完默认**禁用**，启用前复算文件哈希与权限指纹。
- ★ 要出网的插件，其页面**上方**由宿主画一块面板：两栏列清「会发出去 / 不会发出去」，
  要使用者**逐字输入**清单里那句确认话，主进程才替它发第一次请求。插件页面自己画的确认框**不算闸门**，
  一点强制力都没有；撤销允许后 `net.request` 立刻回到被拒状态，宿主顺手清掉替它代管的 Cookie。
  这句话算进权限指纹 —— 作者改它就等于改权限，必须重新导入。被这道门挡下的调用不占用限频额度。
- 每一次调用都重新核对"启用中 + 文件未被改动 + 这项能力批过 + （出网的话）确认还在"；包被改过一个字节就拒绝供能与供页。
- 网络出口只认 https + 标准 443 端口（明文 http 仅限本机回环自测），重定向每一跳复校，`Cookie`/`Host` 由宿主管，
  会话 Cookie 存在 `plugin-data/<id>.cookies.json`（不进导出包、插件的 `kv` 读不到，落盘走临时文件 + rename 的原子写），每插件 60 秒 20 次。
- 插件页运行在 `sandbox="allow-scripts"` 的 iframe 里（刻意不给 `allow-same-origin`），
  拿不到 Node、拿不到 `window.df`，只能经 `DFPlugin.call` 走白名单方法。
  版式由宿主注入一份共享词表（`ui/css/plugin-base.css`，`.pl-*`）——所有插件页只有这一套令牌，
  宿主自己那块确认面板另走 `.gate-*`，两边都在 ≤720 / ≤920 各有一档塌单列；
  并用真实排版引擎量到 360px 宽不破版（`tools/probe-plugin-layout.js`）。
- 卸载会把插件文件、它的配置和它的登录状态一起删掉；撤销确认 / 停用 / 卸载都会立刻掐断该插件正在跑的流。

参照实现与文档：`插件开发指南.md`、`plugins-src/demo-summary/`（不联网的最小例子）、
`plugins-src/team-stats/`（战队战绩同步：登录 → 拼 20 项 → 先看会发什么 → 上传 → 读回核对）、
`plugins-src/ai-analyst/`（★ 联网 + 流式 + 摘要 + 旧数据搬迁的完整例子）。
★ 上面这三份参照实现和 `插件开发指南.md` 都**不在本仓库里**（插件不在开源范围内）；这里公开的是**宿主侧** ——
`core/plugin.js`（能力派发与闸门）、`ui/` 里的插件页与确认面板、`tools/pack-plugin.js`（把插件目录打成可导入的 .zip）、
`tools/probe-plugin-layout.js`（窄屏排版探针）。
回归测试四份：`test/plugin-bridge.test.js`（能力派发与网络出口）、`test/team-stats-plugin.test.js`（20 项口径 + 照文档写的模拟站点）、

### 数据保障（重要）

官方 `GetBattleList` 单页返回 8 条、游标只挪 7 条，翻满 **5 页到 36 条**（阶梯 8/15/22/29/36）。
如果长时间不同步、打得又多，第 36 条之前的场次仍会**永久采集不到**。

| 功能 | 说明 |
|---|---|
| **分页采集** | 设置里可选 1~5 页 + 200~2000 ms 翻页间隔，默认 5 页 / 500 ms |
| **定时自动同步** | 可选 15/30/60/120/240 分钟。v1.3.0 起**启动不再自动同步**，它成了唯一的无人值守路径——不开就会漏场次 |
| **每日自动备份** | 遍历所有 slot 数据文件 + `accounts.json`，每个 tag 独立保留最近 N 份 |
| **完整数据包导出/导入** | 含全部战局与全场名单，换电脑迁移用；导入按房间号去重合并；**包内 `meta.openid` 与当前 slot 不匹配时拒绝导入**（防跨号污染） |
| **漏采自证** | 记录每轮采集窗口；一旦发现「上一轮看到的场次被本轮全部挤出去」就说明中间有场次从未进入采集，侧栏挂红色「疑似漏采」并给出那段空白区间。这类丢失**不可补采**，只能靠把定时同步调密来预防 |
| **清空数据** | 支持两档：仅清空当前号 / 清空所有号 + 账号列表；页内确认对话框（Electron 渲染进程不支持 `window.confirm`） |
| **战绩导出** | 按当前筛选导出 JSON / CSV（含评分列） |

### 关注同场玩家（v1.4.0）

在「单场详情 → 全场完整名单」里点某人的「关注」，之后：

- 他出现在哪一场，战局列表那行就挂「关注 N」徽标，页内还能按「含关注玩家」筛；
- 「状态与节律」页给出**与关注池同场 vs 不同场**的场次、胜率、场均得分、评分与 KD 对比。

三条硬约束：

- **主键沿用全项目唯一的身份聚合规则**（`id:<openid>` 稳定账号 / `nm:<昵称>` 按昵称聚合），
  见上面「同场玩家的身份识别口径」。**只显示当局 4 位临时编号的玩家无法关注**，软件直接拒绝并说明原因——
  那个编号每局重新分配，存下来只会得到一个凭空捏造的「熟人」。
- **只存本机**：这张表装的是别人的账号标识与昵称，因此**不在完整数据包里、不在 JSON/CSV 导出里**，
  换电脑需要重新标记（`store.bundleView()` 的白名单刻意把它排掉）。
- **样本不足不下结论**：分边是随机的、同阵营概率天然约 50%，同场样本不到 20 场时界面只列数字、
  不给「和谁一起更容易赢」这类判断。

### 数据完整度与漏采自证（v1.4.0）

官方只回最近约 36 场，**本机是唯一的历史载体**，所以软件必须能自证「有没有漏」。判据不是猜的：

> 本轮窗口里最老一场 **晚于** 上一轮窗口里最新一场 ⟺ 上一轮见到的每一场都已跌出官方窗口，
> 而这两者之间那段对局从未进入采集。

只要没打满一窗，本轮窗口必然还含着上一轮的场次，判据自然为假——所以首轮不判定、长期没开也不会误报，
不需要任何特判分支。命中时侧栏「上次同步」旁挂红色「疑似漏采」，「状态与节律」页给出那段区间的起止与天数。

另一层是**可疑空档清单**：本机相邻两场间隔超过 3 天的列出来。措辞限定为「这段时间本机没有记录」——
**它不代表那几天你打过游戏**，也无法据此补采，只供你自己核对。空档必须按全部存储场次算，
否则「近 7 天」这类筛选会自己造出一堆假空档。

### 评分口径可配（v1.4.0）

「单局评分」本来就是本软件自己按同局 46~57 人的真实排名加权算的，不是官方口径；v1.4.0 起五档权重
可以在设置里调（填整数即可，和不为 100 也行，读取时归一化）。

- 改动即时生效，所有页面的评分按新口径重算；
- **不改写历史**：之前导出的文件、以及已保存的分析结果仍是当时的口径，「AI 分析」插件页的历史列表会标出「按当时口径」，
  宿主生成的摘要里也带上当前权重串，避免模型误读；
- 那句「得分 35% · 击杀 20% · …」的文案由主进程按当前权重生成后下发，HTML 里不再硬编码第二份。

### 单场小贴士

每场自动生成结论性提示：评分与自身均值对比、本局最强/最弱项（全场排名）、
双方阵营人均分差、干员使用历史、与历史场均对比。

### 战绩卡片

在「单场详情」点「生成战绩卡片」，用 Canvas 绘制一张 780×430 的 PNG，
可保存或**直接复制到剪贴板**分享。卡片含评分、核心数据、全场排名与干员。

### 地图 × 干员 交叉分析

从「看数据」升级到「拿建议」：同一张地图上不同干员的表现对比，
直接告诉你**哪张图用哪个干员胜率最高**，以及不建议用哪个。

样本口径分两道门：一张图 × 一个模式下**至少有两个干员各打过 2 场**才会出推荐；
而推荐本身**不足 3 场的会挂「仅 N 场」**，因为这种行的名次随时会被下一场翻掉。
行不会被偷偷删掉，场次那一列一直在。

### 评分体系

单局评分 0~100，权重：**得分 35% · 击杀 20% · KDA 25% · 占点（次） 10% · 救治 10%**

> **占点（次）不是游戏里的「站点分」**：它是官方给的占领 · 防守据点的**次数**（一场通常个位数）。
> 两份接口都没有站点分字段，站点分只并进了总分 `score`，所以这一列没法和结算面板上的分数对上，
> 数值一个没改，只是把名字写准。

- **有全场名单时**：按你在该局 46~57 人中的各项真实排名取加权百分位（最能反映相对水平）
- **无名单时**：对照固定基准估算

### 其他计算指标
- **救援量化**：场均/分均救治、救治/阵亡比、**救治占全队比例**（需名单）、救治排名百分位
- **击杀明细**：场均/分均/最高/最低击杀、击杀数分段分布、单局击杀 TOP5
- **同局分差**：得分/击杀/KDA/救治/占点（次） 与全场人均、我方人均、对方人均的差值
- **指挥官统计**：手动标记为指挥官的对局单独统计（与胜者为王双归属，不重复计场）

## 架构约束（为二期移动端预留）

`core/` 与 `ui/` **只用纯 JavaScript**，不引用 `fs` / `path` / `http` 等 Node 专有 API。
平台能力（网络、存储、窗口）一律通过**适配器**注入：

| 能力 | 桌面（Electron） | 移动（二期） |
|---|---|---|
| 网络 | `shell/adapters/net.js`（session.fetch，自带登录态） | WebView 内请求 |
| 插件外发 | `shell/adapters/plugin-net.js`（node:https，**不带 cookie / 分区**，与上一条物理隔离、不得合并） | fetch 直连（同一套白名单与闸门语义） |
| 存储 | `shell/adapters/store-node.js`（文件） | SQLite / IndexedDB |
| 窗口 | Electron BrowserWindow | WebView + Capacitor |

二期做 Android 时，**core/ 与 ui/ 零改动**，只替换适配器与外壳。

### 关于竖屏 / 移动端适配（v1.7.0 的诚实边界）

插件这一层已经按竖屏收口了：插件页面只能用宿主注入的一份共享版式词表（`ui/css/plugin-base.css` 的 `.pl-*`），
`≤720px` 一档塌成单列，宽表必须套在 `.pl-scroll` 里横向滚；这条红线不是"看着办"，是 `tools/probe-plugin-layout.js`
用真实排版引擎在 **360 / 390 / 720 / 900** 四个宽度上量出来的（页面横向溢出、控件宽度、最小可点面积都算判据）。
所以已经写好的插件包**不需要为手机重画**，导入即可用。

真正挡路的只有一处：桌面外壳的窗口有 `minWidth: 1080`（`shell/main.js`），它是给桌面定的，不是插件体系的约束。
二期做移动端时，这一条连同侧栏导航的形态要一起换掉——插件本身不用动。

## 合规

- **免费开源 · 严禁倒卖**：软件免费分发，任何渠道收费出售本软件均属侵权，软件内「关于」页已同步声明
- 只读取当前登录账号的战绩数据，用于个人分析
- 不存储账号密码，不导出登录凭据
- 数据仅保存在本机（`%APPDATA%\df-swtwr\`，安卓在应用私有目录）—— 正因为不在安装目录里，
  **下载新包解压覆盖安装不会丢数据**
- **入网只有两发，且都是"只问一句、不带本机任何东西"**：
  1. **地图名字典** —— 官方战绩接口只回地图编号，地名在另一份**公开**的配置表里。为了认识官方新出的地图，
     软件会去取那一份配置表：**打开软件自动取一次，之后距上次超过一天才会再自动取**（平时不占网络），
     也可以由使用者在「设置 → 地图名」里立刻催一次。目的地钉死在那一个 CDN，桌面与安卓各有一道锁；
     落回本机的只有「编号 → 地名」这一份公开字典。
  2. **在线更新 / 装机计数**（v1.8.2）—— 启动时问服务器"现在是哪一版"，有新版本就在「设置 → 在线更新」
     念出来并给出下载地址；**这台机器第一次那一发会多带一个 `sec=启动软件`**，作者据此知道有多少台在用，
     以后只问版本不再计数（是否数过记在本机，重装最多再数一次）。
  两发都**不带登录态**（用的是当场新建、用完就丢的空 cookie 罐）、**不带战绩、不带昵称、不带账号标识**；
  往外**上传**的字节仍然是零 —— 软件不代他下载、不解压、不改动安装目录
- 不做自动化批量请求，不干扰游戏正常运营
- **唯一例外通道**：出厂包不含任何会外发的功能。只有使用者自己导入并启用某个联网插件（如「AI 深度分析」）、
  在宿主面板上逐字输入该插件清单里那句确认话、并自行填入第三方服务商地址与密钥之后，才会有一个字节对外发送；
  此时送出的是宿主生成的去敏聚合摘要，目的地是**使用者自己填的那一家服务商**（详见上面两节的分工表）。
  不导入、或不输入确认句，软件不会有一个字节的对外上传；解锁后随时可以「撤回确认」重新锁定，撤销会一并掐断进行中的请求
